## Standards & Guidelines

- [How to Meet WCAG (Quick Reference)](https://www.w3.org/WAI/WCAG22/quickref/) - The W3C quick reference for the Web Content Accessibility Guidelines, filterable by level.
- [W3C Web Accessibility Initiative (WAI)](https://www.w3.org/WAI/) - Standards, strategies, and resources from the W3C.
- [WebAIM](https://webaim.org/) - Accessibility training and resources, including the annual screen reader user surveys.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) - The current W3C recommendation for making web content accessible.
- [ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/) - W3C specification for accessible rich internet applications.
- [Section 508](https://www.section508.gov/) - U.S. federal accessibility standards and compliance guidance.

## Testing & Auditing Tools

- [axe-core](https://github.com/dequelabs/axe-core) - The leading open-source accessibility testing engine; runs automated checks in browsers and CI.
- [WAVE](https://wave.webaim.org/) - Web accessibility evaluation tool that identifies errors and contrast issues directly in the browser.
- [Pa11y](https://pa11y.org/) - Automated accessibility testing for continuous integration, with a dashboard for trend tracking.
- [Axe DevTools](https://www.deque.com/axe/) - Deque's browser extension and developer tooling built on axe-core.
- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview/) - Google's automated auditing tool that includes accessibility checks.
- [IBM Equal Access Checker](https://www.ibm.com/able/equal-access/) - IBM's open accessibility checker for web and native applications.
- [Accessibility Insights](https://accessibilityinsights.io/) - Microsoft's free tooling for finding and fixing accessibility issues.
- [Stark](https://www.getstark.co/) - Design and development toolkit with contrast, colorblind, and vision simulators.
- [AccessLint](https://github.com/accesslint/accesslint.js) - GitHub bot that flags accessibility issues in pull requests.
- [react-a11y](https://github.com/reactjs/react-a11y) - Linter that warns about accessibility problems in React components.

## Screen Readers

- [NVDA](https://www.nvaccess.org/) - Free, open-source Windows screen reader from NV Access.
- [JAWS](https://www.freedomscientific.com/products/software/jaws/) - Long-standing commercial Windows screen reader from Freedom Scientific.
- [VoiceOver (macOS)](https://support.apple.com/guide/voiceover/mac) - Built-in screen reader for Mac.
- [TalkBack](https://support.google.com/accessibility/android/answer/6283677) - Android's built-in screen reader.
- [ChromeVox](https://support.google.com/chromebook/answer/7031755) - Built-in screen reader for Chromebooks.

## Color & Contrast Tools

- [WhoCanUse](https://whocanuse.com/) - Check color combinations against WCAG contrast requirements for common visual impairments.
- [Colorable](https://jxnblk.github.io/colorable/) - Tool for picking accessible color combinations with contrast ratios.
- [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) - Simple tool for verifying text color contrast.

## Captioning & Transcripts

- [Amara](https://amara.org/) - Crowdsourced subtitling and translation platform for video.
- [Web Captioner](https://webcaptioner.com/) - Free live captioning in the browser via speech recognition.
- [Otter.ai](https://otter.ai/) - Real-time transcription and meeting notes with captions.

## Keyboard Navigation & Focus

- [WebAIM — Keyboard Accessibility](https://webaim.org/techniques/keyboard/) - How to test and design keyboard-accessible interfaces.
- [focus-trap](https://github.com/focus-trap/focus-trap) - JavaScript library that traps keyboard focus within a container.

## Design Systems with Built-in Accessibility

- [U.S. Web Design System](https://designsystem.digital.gov/) - Government design system with accessibility built into its components.
- [GOV.UK Design System](https://design-system.service.gov.uk/) - UK government design system with accessibility standards baked in.
- [Carbon Design System](https://carbondesignsystem.com/) - IBM's design system with accessibility guidance for every component.

## Voice Dictation & Voice Control

- [Apple Voice Control (Mac)](https://support.apple.com/guide/accessibility-mac/use-voice-control-commands-mh40719/mac) - Dictate text and control macOS entirely by voice.
- [Apple Voice Control (iPhone/iPad)](https://support.apple.com/en-us/111778) - Voice-based navigation and dictation for iOS and iPadOS.
- [Google Voice Access (Android)](https://support.google.com/accessibility/android/answer/6151848) - Spoken commands to open apps, navigate, and edit text on Android.
- [Siri](https://www.apple.com/siri/) - Apple's voice assistant for hands-free calls, messages, and app control on iPhone, iPad, and Mac.
